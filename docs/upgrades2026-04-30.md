# Framework Upgrade Notes - 2026-04-30

This upgrade imports generic framework hardening from the downstream application into the reusable osafw baseline. Product-specific entities, fixtures, branding, navigation, external integrations, billing, jobs, and domain-specific admin screens were intentionally skipped.

## Imported

- Core runtime and routing:
  - JSON request parsing now accepts both `CONTENT_TYPE` and `HTTP_CONTENT_TYPE`.
  - Request start logs include the HTTP method.
  - Runtime test hooks can clear framework singletons and inject model instances.
  - Model autoloading supports configured `/models` subfolders through one shared resolver used by runtime autoloading and DevManage discovery.
  - XSS checks fail when the session token is missing.
  - CLI scripts can use `LOG_DESTINATION_OFFLINE`.
  - `ROUTE_ID_REGEX` can override REST ID matching without changing the default route contract.
- Database wrapper:
  - Optional params use explicit nullable types.
  - `LOCAL_INFILE` can be enabled per DB config.
  - Per-query `ping()` was removed; stale connections retry once after MySQL gone-away.
  - `buildUpdate()` keeps SET params when there are no WHERE params.
- Database hardening:
  - `activity_logs.payload` is now `LONGTEXT` for larger structured payloads.
  - `users.fname` and `users.lname` are now `VARCHAR(127)`.
  - `users.iname` generated column is now `VARCHAR(255)`.
  - Framework `locks` table is now part of the baseline schema/update script.
  - attachment raw-data comments now say "regular selects".
- Admin and dynamic CRUD:
  - Base controllers expose overridable `modelOne()` and `modelOneOrFail()` hooks.
  - Admin, dynamic, and Vue CRUD flows use those hooks for show/edit/delete loads.
  - Dynamic autocomplete supports id-bearing values and `autocomplete_limit`.
  - Dynamic textarea fields can pretty-print JSON for display and compact it for save.
  - Checked-list sorting is safer for unchecked rows.
- Storage and support models:
  - Oversized activity log payloads are replaced with a small, valid JSON truncation marker instead of malformed partial JSON.
  - Attachments can transmit table-backed blobs and upload string content while keeping file storage as the default.
  - Default attachment file storage moved to non-public `upload/`; local attachment URLs are served through `/Att/<id>`.
  - S3 helpers support bucket-specific construction, old and new credential shapes, content/URL uploads, object existence checks, and paged recursive delete.
  - S3 response cache controls are included before presigning, and permanent attachment deletion removes the complete per-attachment S3 folder.
  - File-to-table/S3 attachment moves require a readable original before changing storage or deleting local files.
  - Locks use the fixed framework `locks` table shape with `upd_time`/`add_time`, compare expiry in MySQL's clock, expose `exists()`, and retry once after removing an expired unique-key row.
- Generic helpers:
  - `FormUtils::intUniqueArray()`, autocomplete format/parse helpers.
  - `DateUtils::Str2SQL(..., $is_hms)`, exact elapsed-time `differenceMinutes()`, timezone and UTC-offset helpers.
  - `Utils::html2text()`, `Utils::dehtml()`, `Utils::nanoID()`, cURL timeout/curlinfo support, and bounded batch URL loading.
  - ParsePage repeat metadata now includes associative `repeat.key` plus `repeat.even` and `repeat.odd`.
  - ParsePage supports `isLangParse`, safer `selvalue`, JSON modifier improvements, and guarded `nl2br` behavior.
- ParsePage/common templates:
  - `form_list_hidden_fields` hook in `template/common/list/form_list.html`.
  - `tbody_row_attrs` hook in `template/common/list/tbody.html`.
  - `plaintext_json` and `plaintext_url` show renderers.
  - `plaintext_url` only creates clickable links for safe URL schemes; unsafe values render as text.
  - safer text wrapping for `plaintext` and `plaintext_link`.
- Vue common templates:
  - list-header `header_links` support.
  - store parsing for `data-header_links`.
  - virtual Vue index passes `controller_config[header_links]`.
- PHPUnit harness:
  - root `phpunit.xml`.
  - `php/tests/bootstrap.php`.
  - `FrameworkTestCase`, `DatabaseTestCase`, and `ControllerTestCase`.
  - sample unit/model/controller baseline tests.
  - `bin/phpunit-local.bat`.
  - Composer dev dependency and scripts.

## Reworked

- Exception imports were kept generic: `ApplicationException` can carry localization/context metadata, but it does not call the downstream app localization model.
- `BadRequestException`, `NotFoundException`, and `AuthException` preserve framework-compatible constructors while exposing metadata for JSON error contexts.
- The wider downstream string-ID routing behavior was reworked as opt-in `ROUTE_ID_REGEX` instead of changing framework defaults.
- cURL imports keep explicit cleanup and continue treating HTTP 400+ responses as failures.
- Remember-me cookie naming remains backward-compatible by default; a sanitized suffix is appended only when its value is configured through `PERM_COOKIE_ENV_SUFFIX`.
- The established one-argument `FwModel::ilist()` and `Users::doLogin()` override contracts remain intact. Dynamic lookup definitions use the separate `ilistByDef()` extension point, and remember-me cookie changes stay in the login controller.
- Test host resolution uses `OSAFW_TEST_HOST` / `OSAFW_CLI_HOST` and local `php/configs/*.php` auto-detection.
- Database test helpers are limited to generic framework fixtures.
- Controller test helpers only provide dispatch and login/session setup.
- Documentation paths were rewritten to framework paths under `www/`, `php/`, `template/`, `db/`, and `docs/`.
- Public web root was minimized so `php/`, `template/`, and `upload/` live outside `www/`; `www/` now holds the entrypoint and public assets/config only.
- The bundled DB admin tool moved to `php/tools/` and is available only through the existing site-admin `/Admin/DB` route; its fallback public password was removed and server-side dumps go to ignored non-public `upload/dbdumps/`.
- The independent review found unrelated local artifacts in the worktree. `www/ppm.php` and `www/web.config.bak` were moved out of the public web root to ignored agent artifacts, and `.gitignore` now prevents accidental staging if those filenames reappear. Machine-local `php/configs/*.lo.php` host configs are also ignored.
- The branch was synchronized with `master`; its Guzzle, PSR-7, and phpseclib lockfile upgrades were carried into the relocated `php/composer.lock`.

## Skipped

- Redis/Valkey cache replacement because the downstream implementation contains application-specific prefixes.
- Downstream API base controller client headers, client signatures, account secret links, and product JSON helpers.
- Downstream `FwEntities` and `FwLogTypes` product constants.
- Changed attachment default storage; the framework default remains file storage.
- `email_bounced` semantic change from boolean to datetime because no generic bounce handling was imported.
- Product fixtures and domain-specific records.
- Domain-specific model/controller helpers in database and controller test cases.
- Branded navigation, app-specific header links, and product-specific Vue screens.
- Third-party service test scaffolding and credentials.
- Downstream-only docs that describe product APIs, billing, push notifications, AI integrations, or operational jobs.

## Migration

Apply the dated update script under `db/updates/` to existing framework databases. New installs get the same schema from `db/fwdatabase.sql`.

The locks migration drops and recreates `locks` with the fixed framework table shape. Existing active lock rows are discarded during the upgrade.

For tests, install dev dependencies from `php` and run:

```bat
bin\phpunit-local.bat localhost
```

or:

```powershell
$env:OSAFW_TEST_HOST='localhost'
Push-Location php
composer test
Pop-Location
```

DB-backed tests skip themselves when no usable DB config is available for the resolved host.

The repository tracks vendor files but this upgrade intentionally does not refresh them. Run `composer install` from `php` after checkout/deploy so installed packages match `php/composer.lock`.
